# NixOS 25.11 Deployment Notes

**Date:** 2026-04-28
**Status:** Draft

## Deployment model
- Run `mcp-justwatch` as a local systemd-managed process.
- Bind the Python service to `127.0.0.1` only.
- Reverse proxy `/mcp` and `/health` through Nginx.
- Expose only ports 80 and 443 publicly.
- Terminate TLS at Nginx using ACME.
- Prefer API-key enforcement at the proxy layer for the first remote deployment milestone.

## Environment variables
- `MCP_JUSTWATCH_TRANSPORT=http`
- `MCP_JUSTWATCH_HOST=127.0.0.1`
- `MCP_JUSTWATCH_PORT=8000`
- `MCP_JUSTWATCH_LOG_LEVEL=INFO`
- `MCP_JUSTWATCH_LOG_FILE=` (leave empty for journald-oriented logging)

## NixOS service shape
Recommended characteristics:
- dedicated unprivileged service user
- `Restart=on-failure`
- working directory set to the checked-out application directory or packaged output
- environment variables provided through `systemd.services.<name>.environment`
- no direct public listen socket on the application process

## Nginx shape
- `services.nginx.enable = true`
- `services.nginx.recommendedProxySettings = true`
- `services.nginx.recommendedTlsSettings = true`
- virtual host with `enableACME = true` and `forceSSL = true`
- `/mcp` proxied to `http://127.0.0.1:8000/mcp`
- `/health` proxied to `http://127.0.0.1:8000/health`

## Firewall shape
- keep firewall enabled
- allow only TCP 80 and 443 publicly
- do not open the internal application port

## Router and DNS
- create a DNS record pointing at the public IP
- forward TCP 80 and 443 from the router to the NixOS host
- if public IP is dynamic, use dynamic DNS or DNS-01 ACME flow

## Verification checklist
- local process starts and binds to loopback
- `curl http://127.0.0.1:8000/health` returns `OK`
- Nginx reverse proxy serves HTTPS successfully
- external `/mcp` endpoint is reachable only through Nginx
- Perplexity remote connector validates against the HTTPS endpoint
